# 星标写入时把条目挪到次序之首

**Status**: accepted

[ADR 0004](0004-star-mark-on-a-complete-entry.md) 定下「星标只是记号，不改变**次序**」。主人在真机上用过之后改了主意：点星就是要它出现在最上面。这与 0004 的表述直接冲突，所以重新决定，而不是悄悄改代码。

决定：**星标**的值与位置是同一笔写入。`starAndMove`（`src/domain/verbs.ts`）在同一个数组里既写 `starred`，又把它排到本**分组**的**次序**之首：加星 → 第 0 位；减星 → 未带星区的首位（即已带星块正下方）。`setStarred` 仍是一次结构性落盘，不拆成「写值」加「重排」两次。

星标仍然是**记录值**：随**法典**导出与导入，备份格式不升版（值和位置都在同一份 `verbs` 数组里）。

但「星标在上」**不是不变量**。加载不排序，也不按星标分区；拖动仍可把带星条目拖到未带星条目之下，法典不纠正。这是主人明确要的：不 toggle 就不干预拖拽。

## Considered Options

- **星区末尾**（新星排在旧星之后，旧星保持相对顺序）：否决——主人要的是「置顶」。列表一长，「往上挪了几位」看起来像没生效。
- **拖动时夹住跨边界**（把「星在上」做成真分区）：本版否决——Android 与 web 两套拖动都要改，工作量翻倍，而主人说了不干预拖拽。
- **按 `starred` 或 `createdAt` 排序**：否决——**次序**是主人亲手排的**记录值**，自动排序会抹掉他的劳动，这正是 0004 之后的**次序**定义所反对的。
- **加一个「星标区」列表**：否决——星标不是**分组**，它不改变条目站在哪个列表里。

## Consequences

- 按下记号后那条会离开原位。本版不做动画，所以它是瞬移；行移出视口时，看到的是它「上去了」而不是过程。
- **检索中点星也会移动**，而且位置是对的：移动在领域层按 `id` 算，不依赖列表索引，所以过滤后的子集不会成为坐标系（拖动在检索时被禁用，正是因为它的 `slot` 是分组内索引）。
- 拖动可以把带星条目拖回下面；此后列表不再「星在上」。这是允许的，不是 bug——**星标**是一次跳转，不是分区。
- 旧版本导入再导出会丢掉**星标**（字段被忽略），但已经发生的移动留在**次序**里，回不去。
- 同一格记号仍承载两笔事实：完整性（读出）与星标（写下）。这一条没有变，见 0004。
