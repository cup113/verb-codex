# 星标是条目上的一笔记录，不取代完整记号

**Status**: accepted

产品要列表的完成记号（✓）长按两秒变成 ★。这与 CONTEXT 的一条不变量直接冲突：完成记号是从六个**变位行**读出的事实，不另存字段——而星要在关掉 App 之后还在，就必须落盘。决定：**星标**是**动词条目**上的一个**记录值**（`starred`），随**法典**导出与导入，备份格式不升版；记号三态 ○ → ✓ → ★，★ 只画在**完整**的条目上，缺一行的星标条目仍画 ○——完整永远不被星掩盖。星标不改**次序**、不做筛选、不参与**自测**/**默写**，它只是记号。

## Considered Options

- **独立账本**（像**复习箱**那样按键记账）：否决——复习箱记的是法典自己的账，星是主人对某一条的书写，应当随条目一起走。
- **纯视觉、不落盘**：否决——关掉 App 就消失，主人会以为丢了东西。
- **缺行也画 ★**：否决——列表唯一的完整性信号会被星遮住，星标条目变得不完整时列表会说谎。
- **缺行即清星**：否决——删掉一行就静默丢掉主人写下的标记。

## Consequences

- 同一格记号承载两笔事实：完整性（读出）与星标（写下）。星只在完整时出现，所以「看到 ★」仍然蕴含「已完整」。
- 星标条目失掉一行时星留在条目里但不可见，补满六行后自己回来——这是不丢记录付出的代价，也是完整优先的直接结果。
- 旧版本导入再导出会丢掉星（字段被忽略、下次导出不写），条目本身不受影响；这与**主人**名的处理相同，因此不升格式。
- ★ 与默写印章的 ✦ 因此需要同一张小字面，从合并汉字字面（3.5 MB 的下载栅栏）里分出来（见 `tools/make-symbols.py`）。
